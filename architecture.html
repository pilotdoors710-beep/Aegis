Aegis architecture

Runtime security middleware for autonomous browser agents. Aegis sits between an AI agent and a live page, checks every action the agent proposes, and answers ALLOW, BLOCK, REROUTE or ASK before it runs. Before anything irreversible it compares the checkout with what the user actually asked for.

1. Overview

The project is a hackathon entry. It is two programs plus a database:

web/ (Next.js on Vercel)

The Shield Console, Sybil playground, Scan, Trap Lab, Runs replay and Stats pages, plus the static Trap Arena shop "Aurora Home" in web/public/arena/.

server/ (FastAPI + Playwright)

One Python process with one shared Chromium. Runs the agent twice at once (with and without Aegis), applies the shield, streams events over SSE.

Supabase

Postgres for runs, events, LLM decision cache and Sybil records; Storage for screenshots. Optional: without it the server keeps everything in memory.

LLM providers

Free tiers (Groq, Gemini, OpenRouter, Cerebras) through OpenAI-compatible endpoints. Default model groq:openai/gpt-oss-20b.

The core demo: the same agent gets the same task ("Buy one Aurora desk lamp for under ₹1,500, standard shipping") in two browser contexts. The left side runs unprotected; the right side runs through Aegis. Traps in the shop (click-jacking, pre-ticked plans, hidden fees, prompt injections…) catch the left side; Aegis catches them on the right and the console shows what each side bought and paid.

Everything in the arena is simulated: charges, orders, data and downloads. Aegis has only been tested on its own shop. The backend is hosted on a developer PC exposed with Tailscale Funnel, not a cloud VM.

4. Step-by-step walkthrough

  1. Pick a preset. /console lists presets from GET /presets (defined in server/aegis/presets.py; the web never hardcodes a task). Presets include main-demo (T02 click-jacking), clean, one per trap, r1-forbidden/r1-authorized (same checkout, plan forbidden vs allowed), r2-consent, cloaked (T11 with R2) and sybil-two-shop.
  2. Create the run. POST /runs checks the preset, freezes Sybil evidence if needed, registers a RunSummary and an AskGate on the RunBus, and starts _run as a background task. The console subscribes to /runs/{id}/stream.
  3. Write the ledger. intent.parse_ledger turns the task text (and only the task text) into a Ledger with one LLM call. Page content can never change it. If parsing fails, the Aegis side asks the human before browsing.
  4. Open two sides. loop.run_pair runs run_side for unshielded and shielded in parallel, each in a fresh Playwright BrowserContext on the shared Chromium, with a frozen clock and an egress guard that blocks everything except the arena origin.
  5. Snapshot. Each step, snapshot.js runs once in the page and returns every element with geometry and visual facts (opacity, contrast ratio, what covers it). On the Aegis side the fast detectors run page-wide first, so B5 (injections) and C1 (pressure widgets) can be removed from what the agent sees.
  6. Agent view and decision. agent.build_agent_view is the only place the agent's view is built: detector-only fields never reach the model. agent.decide calls the LLM through llm.py and gets back one Action.
  7. Unprotected side executes the action straight away. Aegis side sends it to StepShield.check:
    • fast detectors A1–A5, B5, C1 and a neutralization plan for click-jacking overlays;
    • the Sybil shop gate (only when the run has graph evidence);
    • fail-closed: a crashed or timed-out check becomes ASK;
    • for irreversible actions: the B2 audit of the visible checkout against the ledger, optionally an R2 trial for an ambiguous consent box, then the two-view check.
  8. Act on the verdict. ALLOW executes. BLOCK/REROUTE feed evidence back and the agent picks again (3 retries, then ASK). ASK pauses for the human; on approval the checkout is re-audited, because approval covers exactly the checkout that was shown.
  9. Execute. executor.execute always clicks with page.mouse.click(x, y) at the target's centre (never locator.click(), whose safety checks would protect the unprotected side). The Aegis side re-runs the hit-test right before the click.
  10. Finish. A side ends when the confirmation page is visible, the agent says done, it is denied, it errors, or it hits 15 steps. pages.outcome_from_page reads only what the confirmation shows.
  11. Show and keep. Every step emitted an event (snapshot, decision, verdict, ask, executed, error, done). The bus streams them over SSE and writes them to Postgres, with screenshots in Supabase Storage. The console renders outcome cards; /runs replays any stored run.

5. Key concepts

Verdicts

DecisionMeaningWhat happens next
ALLOWNo finding on the action's target.Executes. Page-wide findings still ride along so the console can box them.
BLOCKThe target itself is a trap (hidden, covered, lying link…).Not executed; evidence goes back to the agent; it chooses again.
REROUTEThe audit found the checkout violates the ledger (e.g. pre-ticked plan, hidden fee).Not executed; a correction hint goes back; the agent fixes it; Aegis re-audits.
ASKFinal payment, personal data, uncertainty, untrusted shop, broken check or retries used up.Pauses for the human (Approve / Deny). Auto-approval is always labelled as simulated.

6. Sybil: link-based trust for shops
